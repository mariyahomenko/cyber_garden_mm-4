# CyberDoc — техническая документация

## 1. Назначение

CyberDoc — настольное приложение на Python и PyQt5 для работы с научными PDF-файлами. Приложение загружает несколько документов, извлекает текст, выполняет поиск, формирует ответ через DeepSeek или GigaChat, связывает ответ со страницами документа и открывает PDF с подсветкой найденных фрагментов.

Поддерживаются два сценария предметного ТЗ:
- **Solar** — параметры и результаты тонкоплёночных солнечных элементов.
- **RAG** — метрики информационного поиска и RAG.

Модуль «Научные данные» извлекает кандидаты, показывает исходные фрагменты, выполняет проверки и экспортирует JSON и 7 CSV в формате сдачи.

## 2. Структура проекта

- `main.py` — точка запуска.
- `cyberdoc/app.py` — создание QApplication, тема и жизненный цикл приложения.
- `cyberdoc/ui/main_window.py` — главное окно, библиотека PDF, запросы, история ответов и выбор провайдера.
- `cyberdoc/ui/answer_window.py` — отдельное окно ответа, поиск по ответу, копирование и масштабирование.
- `cyberdoc/ui/pdf_viewer.py` — просмотр страниц, масштаб, поиск, закладки, выделение областей и копирование текста.
- `cyberdoc/pdfdoc.py` — открытие PDF, порядок чтения колонок, OCR, поиск и координаты подсветки.
- `cyberdoc/client.py` — общий HTTP-клиент, DeepSeek, OAuth-авторизация GigaChat и повторные попытки.
- `cyberdoc/research.py` — извлечение и проверки структурированных показателей (solar).
- `cyberdoc/research_rag.py` — извлечение и проверки для RAG-домена (7 таблиц по `schema.json`).
- `cyberdoc/export_rag.py` — экспорт 7 CSV RAG-домена.
- `cyberdoc/research_dialog.py` — интерфейс предметных данных, переключение домена solar/rag.
- `cyberdoc/renderer.py` — HTML ответа, формулы и ссылки на страницы.
- `cyberdoc/theme.py` — тёмная тема и единые стили контролов, `style_combo()`.
- `cyberdoc/export_utils.py` — экспорт паспорта и набора данных.
- `tests/` — модульные проверки, которые можно запускать в окружении с pytest.

## 3. Запуск

    python -m venv .venv
    # Windows: .venv\Scripts\activate
    # Linux/macOS: source .venv/bin/activate
    python -m pip install -r requirements.txt
    python main.py

Для OCR сканированных страниц рекомендуется установить Tesseract OCR с языками `rus` и `eng`. Приложение сначала использует `pytesseract`, а при его отсутствии пытается использовать OCR-мост PyMuPDF. Если OCR-движок недоступен, исходное изображение PDF сохраняется и просмотр остаётся доступным.

## 4. Интерфейс

Шапка главного экрана — компактная, высотой 44 пикселя. Левая библиотека PDF открывается шириной 380 пикселей, чтобы заголовки и подписи читались полностью. Панель сворачивается кнопкой `‹` и разворачивается `›`.

Окно ответа использует кнопки `−` и `+` в том же стиле, что и основные элементы главного окна. Масштаб применяется повторной сборкой HTML, изменяя CSS-размеры шрифта и ширину формул. Процент отображается информационной подписью без отдельной кнопки.

В просмотрщике PDF кнопка «Выделить текст» включает прямоугольное выделение. Текст из текстового слоя копируется в буфер обмена. Для скана используется OCR по координатам выделенной области.

## 5. Авторизация и секреты

Исходный код не содержит API-ключей, Client Secret или access token. При первом запросе ключ вводится в защищённое поле диалога и хранится только в памяти текущего процесса. `QSettings` сохраняет тему, провайдера, геометрию и открытые пути, но не credentials. При закрытии главного окна ключ, Client ID и OAuth token очищаются.

DeepSeek использует `Authorization: Bearer <key>` и потоковый ответ. GigaChat использует OAuth 2.0: из Client ID и Authorization key формируется Basic-заголовок, затем запрашивается access token с `RqUID` и `scope`. Обработаны оба формата `expires_at`: epoch milliseconds и ISO 8601. Токен кэшируется только в памяти, обновляется перед истечением и сбрасывается после HTTP 401.

Рекомендуется задавать только безопасные параметры подключения через переменные окружения:
- `DEEPSEEK_API_URL`, `DEEPSEEK_MODEL`.
- `GIGACHAT_API_URL`, `GIGACHAT_OAUTH_URL`, `GIGACHAT_SCOPE`.
- `GIGACHAT_VERIFY_SSL=1` для проверки сертификата.

Секреты через переменные окружения в архив не включаются.

## 6. Работа с PDF

При открытии документ читается через PyMuPDF. Текстовые блоки сортируются по координатам. Для двухколоночной статьи сначала собирается левая колонка, затем центральные блоки и правая колонка. Для страниц без текстового слоя запускается OCR. OCR-слова добавляются в поисковый индекс и используются для копирования выделенного участка, а исходная страница продолжает отображаться как изображение.

Поиск поддерживает точную фразу, слова запроса, вхождение внутри слова и регулярное выражение. Для каждого результата сохраняются номер страницы и прямоугольник. По найденному результату просмотрщик центрирует страницу и рисует подсветку.

## 7. Формат ответа и навигация

LLM получает контекст выбранных страниц и системные правила формата. Формулы передаются отдельными маркерами `[[FORMULA ...]]`, а ссылки на цитаты — `[[REF ...]]`. Рендерер превращает их в HTML. Ссылки на страницу открывают нужную страницу PDF и пытаются подсветить координаты цитаты.

История ответов хранится в памяти текущего запуска и поддерживает переходы назад и вперёд. Ответ можно скопировать целиком или открыть в отдельном окне. В отдельном окне доступен поиск по тексту ответа.

## 8. Научные данные и экспорт

Модуль предметных данных показывает домен, сущности, параметры, значения, единицы, страницы и исходные фрагменты.

**Solar.** Схема включает публикацию, материал, прибор, слои, условия измерения и результаты PCE, Voc, Jsc, FF, Rs, Rsh и T80. Экспорт — 7 CSV (`publications, materials, devices, layers, measurements, results, issues`).

**RAG.** Схема включает публикации, конфигурации, наборы данных, задачи, эксперименты, результаты и замечания. Метрики: Recall@k, Precision@k, MRR, NDCG, EM, F1, BLEU, ROUGE-L, UniEval, tokens per query, latency. Экспорт — 7 CSV по `submission_template/schema.json` (`publications, configurations, datasets, tasks, experiments, results, issues`).

Таблицы и рисунки с метриками, которые строковый парсер не извлёк, попадают в `issues.csv` как `present_not_extractable` — это соответствует ТЗ: «значение действительно обозначено, но достоверно извлечь его из доступного PDF нельзя».

Экспорт не заменяет проверку человеком. Значения без условий эксперимента сохраняются как кандидаты и должны быть сверены со страницей статьи.

## 9. Проверка перед поставкой

1. Установить зависимости из `requirements.txt`.
2. Запустить `python -m compileall -q cyberdoc`.
3. Запустить `python -m unittest discover -s tests -v`.
4. Открыть обычный текстовый PDF и проверить поиск, копирование и масштаб.
5. Открыть сканированный PDF при установленном Tesseract и проверить OCR-поиск и выделение.
6. Проверить DeepSeek и GigaChat с тестовыми credentials, не записывая их в файлы.
7. Проверить смену темы, сворачивание библиотеки, открытие окна ответа и экспорт JSON/CSV.
8. Проверить сабмишн: `python tools/check_submission.py <папка> test --json-report report.json`. Код 0 или 2 — допустимо, 1 — ошибка структуры.

## 10. Известные внешние зависимости

Для сетевых запросов требуется доступ к API выбранного провайдера. Для OCR требуется установленный движок Tesseract. Без него сканы можно просматривать, но поиск по изображению и копирование распознанного текста недоступны. PyQt5, PyMuPDF, requests, Pillow и matplotlib устанавливаются из `requirements.txt`.
